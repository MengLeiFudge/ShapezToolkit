# TMAM-XianYu-20221129 的拆解思路

这台机器把目标结构拆成少量有固定加工方法的部件，再尝试几种堆叠顺序。拆解选择由带反馈的控制电路完成：一轮没有拼回目标，就重新加载目标并改变选择状态，继续尝试。

Python 保留这套控制过程。控制器中的寄存器、逻辑门、延迟和冲突规则与存档对应；部件的制造步骤和最终拼装写成普通 Python。求解过程中不查可制作图形数据库，也不读取原始存档。

## 输入和工作状态

当前接口处理四层、每层四角的占用结构，用无色圆形表示存在的角块。16 位整数的低四位是底层；层内各位依次对应右上、右下、左下、左上。目标中的颜色不参与结构枚举，控制器内部的颜色和形状标记仍保留，因为它们用于传递指令。

机器并不只保存“剩下的图形”。它还保存目标副本、四个工作层、选择模式、朝向、当前加工指令，以及最多五个部件。相同的剩余结构，在不同模式和朝向下可能进入不同的选择分支。因此，不能只凭剩余图形判断机器下一步的动作。

## 一轮拆解怎样进行

启动时，目标送入目标寄存器和工作层。控制电路轮转朝向，检查当前层和相邻层的角块分布，结合模式和上一条指令，选择下一种部件。单层支路处理直接可准备的单层；其余支路生成悬空双角、交错角或双列部件的加工指令。

选出部件后，电路通过切割、保留和工作层寄存器更新，去掉已选部分。指令先保持，再经过延迟链送到加工区域；制出的部件恢复朝向后，以脉冲写入部件寄存器。部件寄存器有保持和移位过程，所以发出指令、得到部件、写入部件并不是同一 tick 的动作。

最多五个部件进入四条拼装支路，每条支路按自己的堆叠顺序生成候选图形，再与原目标比较。若当前组合没有得到目标，反馈电路产生重试脉冲，重新加载目标，并推进后续模式、方向等状态。重试不是对同一批部件无限重复相同的堆叠。

如果完整控制状态重复，之后也会重复相同过程，Python 将其报告为周期。达到计算上限但尚未确认固定点或周期时，只报告超时。成功要求目标输出和相等检查持续成立，瞬间相等不算完成。

## 指令如何变成可制作的部件

指令由三部分组成：`载荷:模板标记:朝向标记`。载荷是一层或两层图形；后两项只传控制信息，不进入成品。

朝向标记中唯一的 `R` 指定部件最终朝向。四个位置分别对应顺时针旋转 0、3、2、1 次。除单层模板外，加工前先把载荷顺时针转三次，将待加工部分放到模板约定的方向。

[decode_recipe](solver.py) 展开以下七种模板：

| 模板 | 加工思路 |
|---|---|
| `SuSuSuSu` | 直接准备载荷单层，再恢复朝向 |
| `CrCrCrCr`、`CbCbCbCb` | 两片单层原料分别搭配半方块支架；按相反先后堆叠，再旋转、切掉支架，留下两层悬空部件 |
| `RrRrRrRr`、`RbRbRbRb` | 取三片单层原料，搭配支架后按模板指定的顺序堆叠、旋转和切割，留下交错部件 |
| `WrWrWrWr`、`WbWbWbWb` | 从两列各取上下单层，用四片原料和支架拼装；两种模板的堆叠顺序不同，蓝色模板还调整最后一片的方向 |

支架先提供碰撞和高度，随后被切掉，从而保留目标中的悬空结构。加工树中的原料必须是非空单层；多层悬空部件必须由步骤制造，不能作为现成原料。控制器读取指令时使用的虚拟拆层只用于解释载荷，不是加工树中的实体操作。

`Plan` 记录每一步操作及其输入，最终加工树只包含单层原料、堆叠、顺时针旋转和右半切割。这里的堆叠遵循游戏规则：上方图形作为整体下落，碰撞决定高度，超过四层的部分被截断。

## 为什么保留四种拼装顺序

设五个部件为 A、B、C、D、E，`S(底部, 顶部)` 表示堆叠。部件齐全时，四条支路对应：

```text
S(A, S(B, S(C, S(D, E))))
S(S(A, B), S(C, S(D, E)))
S(S(A, S(B, C)), S(D, E))
S(S(S(A, B), C), S(D, E))
```

堆叠顺序会影响中间产物的下落和四层截断，因而这些表达式不能互换。少于五个部件时，只有存档实际设置了旁路的位置可以跳过空值；不能把所有空值都当成堆叠的单位元。

`assembly_candidates` 按实际支路计算候选值；确认候选与电路输出一致后，`assemble_plans` 生成对应的加工树，再核对整棵树是否还原目标。

## Python 怎样保留游戏时序

[controller.py](controller.py) 中的 `EQUATIONS` 保存同步状态方程。每条方程列出输出寄存器、运算和输入导线的全部信号提供者。关键寄存器使用含义名称，其余名称保留建筑坐标，便于回到存档核对。

| 名称 | 作用 |
|---|---|
| `target_register` | 保持原目标，供重载和结果比较使用 |
| `phase_register` | 保持选择模式和方向状态 |
| `single_layer_recipe`、`four_corner_recipe`、`alternating_recipe`、`floating_pair_recipe` | 各种部件的指令选择支路 |
| `recipe_register`、`recipe_to_factory` | 保持当前指令，并延迟送入加工区域 |
| `decoded_part`、`part_1` 至 `part_5` | 部件输出脉冲及部件保持、移位 |
| `start_pulse`、`retry_pulse` | 启动和重载目标的脉冲 |

例如，指令保持方程为：

```python
(('recipe_register',), IF, ('hold_recipe',), ('g_65_m6', 'recipe_register'))
```

它读取上一 tick 的输入网络：允许信号成立时，把第二个网络的值写入下一 tick 的寄存器。第二个网络同时连接新指令和旧寄存器输出；两者同时输出不同值会发生冲突，所以不能替换成普通的 `new_recipe or old_recipe`。

[tmam_verify.py](../tmam_verify.py) 中的 `CircuitModel` 负责逐 tick 执行。每 tick 先应用外部输入和开关，再汇总导线信号，最后让所有逻辑门读取这一批网络值并更新输出。后面的门不会提前读到本轮刚更新的门输出。串联门、反馈、保持和脉冲延迟均保留。

`NULL`、布尔 `FALSE` 和布尔 `TRUE` 是不同信号。网络忽略 `NULL`，多个相同的非空值可以合并；不同的非空值产生冲突，接收门清空本 tick 的全部输出。`FALSE` 也是非空信号，必须参与冲突判断。

## 阅读代码

从 [XianYu20221129.solve](solver.py) 开始：它先在关闭开关的状态下换入目标、等待稳定，再开启开关运行控制器。得到持续成功的结果后，根据实际指令重建部件加工树，核对四条拼装支路，再返回最终路径。每个输入独立复位，不继承上一个失败输入的周期状态。

继续阅读同文件的 `decode_recipe` 和 `assembly_candidates`，可以看到实体加工步骤与拼装顺序。选择条件、反馈和时序细节在控制器的 `EQUATIONS`；基础信号与图形运算在 [tmam_signals.py](../tmam_signals.py)。

这套说明适用于整个输入结构空间。具体案例、覆盖数量和对照证据放在本机 `verification/` 目录中；命令和调用方式见 [README](README.md)。控制器仍是存档电路的忠实转录，尚未化简为一套脱离时序的简短几何判定规则。
