# 虚拟六槽整单确认

本件内置六槽单步并维护一份虚拟槽状态。它从候选总线接收六字段，成功提交后按原地址回 ACK。主控报整单完工后，本件发布累计长度和成品核对结果。

```bash
python -m shapez2_tmam.circuits.compiler_backend.virtual_recipe_replay \
  --output virtual-recipe-replay.spz2bp
```

默认容量为 971 笔，地址范围为 `0`–`970`。导出固定容量样件可用 `--max-packets` 指定 `1`–`971`。蓝图和同名 JSON 一起交付。

| 方向 | 频道 | 信号 |
| --- | --- | --- |
| 输入 | `1680001`–`1680006` | `opcode/a/b/destination/base/color`，未用字段保持空信号 |
| 输入 | `1680007` | 当前候选地址，首笔为整数 `0`，空信号表示暂无候选 |
| 输入 | `1701695` | 运行使能，整数 `0` 复位，`1` 运行 |
| 输入 | `1701699` | 方法主控总完工 |
| 输入 | `1600000` | 本单目标图形 |
| 输出 | `1702740` | 同址 ACK，空信号表示当前没有确认 |
| 输出 | `1702741` | 已成功提交的笔数，复位为 `0` |
| 输出 | `1702742` | `finished`，当前批次的成品核对完成 |
| 输出 | `1702743` | `accepted`，唯一成品位于槽 `0` 且等于目标 |
| 输出 | `1702744` | `result`，完工时唯一的槽 `0` 成品。目标不匹配时仍可读到实际图形 |
| 输出 | `1702745` | `fault`，地址越序、超容量、被拒绝的操作或采样时请求不在位 |
| 输出 | `1702746` | 写入方可读取的待提交地址，提交后保留旧地址至 ACK 同拍切换 |

## 时序

1. 换单时保持 `enable=0` 至少 96 信号 tick，准备稳定的目标并等主控总完工清零。复位清空六槽、累计长度、最后确认地址与错误，首笔从地址 `0` 开始。
2. 同拍发布地址与六字段，并保持到同址 ACK。单步稳定期开销见接口表。收到 ACK 后可撤销地址或直接发布下一笔。保留或重发最近成功的地址会再收到 ACK，六槽和累计长度按第一次接受的结果保留。
3. 若 `fault=1`，维持本次提交前的槽与计数。完成换单复位后从地址 `0` 重开。
4. 收到末笔 ACK 后，方法主控才发布 `done=1`。等 `finished=1` 后读取 `accepted`、`length` 和 `result`。目标信号从开单保持到本次核对完成。空单、其他槽余料或唯一成品不在槽 `0` 均无法通过验收。

本件的 ACK、计数与验收都有独立输出。接入写入方时按上表绑定虚拟地址与回报。实体工道的回读和写入确认由其自身接口提供。

离线使用原生接线与 12 信号 tick 的无线模型，执行了悬空订单的 145 笔操作，每笔六槽与实体配方回放逐槽一致，最终槽 `0` 与目标相等。还核对了同址重发、无效停机、目标不匹配、错误成品槽、中途复位，以及从累计长度 `970` 提交最后一笔后拒绝地址 `971`。游戏内时序待验。
