# 四象限五层整厂约定

本目录的四象限五层蓝图按通用火车、配料、制作、电路四册交付。固定目标求解一次，制作层重复执行成功配方，稳定生产时交付一满带目标图形。

| 分册 | 输入 | 职责与输出 |
|---|---|---|
| 通用火车（`火车/`） | 各地原料或染料 | 每列车的所有载货车厢只运同一种货，将货物送到配料站。通用车站能服务不同厂区 |
| 配料（`配料/`） | 各种单料列车 | 分别卸货、按固定装载表重组、装上混合列车，再由混合列车向制作层供货 |
| 制作（`实体/`） | 目标信号、配方、混合列车运入的全部原料和染料 | 把目标发给电路层，等待判定和配方。可解时组织进料、加工与成品输出 |
| 电路（`电路/`） | 任意四象限五层范围内的目标信号 | 按完整合成算法判定并返回结果，可解时给出有序配方、物料种类和每件成品的消耗。保留理论的供料范围及未界定状态 |

## 设计顺序

1. 先在理论和 Python 中选定制造路线。按优先顺序给出每条路线的覆盖条件。上一条已经覆盖的目标直接归入上一条。只有剩余目标确实需要不同处理时才增设分支。比较路线时优先考察能共用的工序、控制状态和模块，允许多执行几步来省掉一整块电路。互不依赖的工序可并行，耗时按最长的依赖链估算。
2. 先实现电路层。用统一接口返回可制作性、配方及用料。先用游戏虚拟加工电路逐条回放配方，核对结果与目标一致，再定指令接口和各模块调用方式。布线前先估算建筑数和电路复用后的耗时。
3. 按电路输出的指令设计实体加工线，确定一满带成品所需的原料种类与供给率。最后设计备料、配料和火车站场，依照已确定的供料需求安排车厢层位。

## 电路模块

从算法中独立的职责确定模块及上下级。每个模块写明调用者、参数、返回值、何时可读取。相同功能用时序调用复用，独立计算可并行。每块先按这些接口单独设计和压缩，再组合成上层电路。

模块边界、三层布置、自动走线和体积验收按[电路走线与压缩](电路走线与压缩.md)执行。

## 装载与配方

混合列车按车厢和层位编排。一格最多三种货，同一层的四条带均属同一种原料。图形和染料使用各自的车厢与装卸接口。吞吐量较大的原料可占多个层位。配料站装车和制作厂卸车使用同一份装载表，换目标保留层位定义。

选配方时兼顾外运货种、每件成品的原料和染料用量，以及厂内加工能力。可由厂内旋转得到的异向原料能共用货种。计量保留每一次物品消费，包括临时支撑和加工副产物。普通物品按件计，染料按加工的实际流体量计。固定货种、每层四带的上限和列车的平均到货量分别核算。

## 从代码生成电路

Python 方法描述输入、输出、图形操作和算法。编写方法时只维护这部分源码。游戏建筑的选型、摆放、接线及蓝图编码由通用编译器负责。编译器按所支持的类型、操作和控制流工作，同一编译规则适用于不同方法和其他 TMAM。

指定一个方法即可在本地自动生成游戏建筑、接线和输入输出接口，编译过程无需 AI 参与。方法可单独导出，也可由上层模块调用。固定大小的状态和循环编译为可复用的时序电路。遇到不支持的类型或操作时，编译器指出源码位置。部件通过编译后，按四册装配并核对接口。

## 整厂验收

1. 游戏中的制作层提交目标，电路自行判定并交付配方。不可解目标有明确结果。
2. 同一份配方能在实体工道上执行。记录基础料、各步操作数次序、副产物出口和目标成品。换目标前清理占用的工道和物料状态。
3. 从单料车卸货开始，逐个核对配料、混合车装卸及厂内入口。逐层核对四条带的货种和方向。
4. 对固定可解目标，以一满带成品为基准，核对各道工序的加工率、每种货的持续供给率和列车到站间隔。供料仓只作缓冲。实机验收记录带速档位、目标、观测区间、进货与出货数量。

源码、部件蓝图、完整装配、静态核对、游戏内整厂验收各自记录进度。
