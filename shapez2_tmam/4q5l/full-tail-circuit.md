# 五帧完整尾部电路与成功路径重放

[`build_solver`](../full_solver_circuit.py)把[完整四象限逆推](tail-solver.md)编成一份原生纯电路蓝图：[`full-tail-4q5l.spz2bp`](../blueprints/full-tail-4q5l.spz2bp)。它接收原目标与enable，搜索成功后输出完整消费式制造指令，并在游戏虚拟操作中回放到原目标。

本页的完整性沿用任意无晶体单层基础料、合法普通部件、rgbcmyw晶体供料及五层局部物理前提。cu供料仍返回3。本版已接全搜索与发令控制，尚未通过实用规模和等待时间验收；没有运行目标、搜索、指令、反馈模拟、测试或游戏。

## 1. 状态与共用通路

最多五帧，每帧保存20格目标ID、12位S前缀、四个五位来源槽号、四个两位NPC顶盖、四个顶层C位及一个搜索遍次位。原目标固定供24项标签表使用；所有递归候选只保存编号，不伪造任意含C图形原料。

共享通路包括材料查询、S支撑检查、两个切向的半形判据、四列Pin候选及必要筛选、三个原生结果比较器、一份486行ROM和六物品槽。ROM前475行是两遍共用的起点加S程序，后11行是一次Pin与五对基础层/Stack尾程序。

[`ClockedState`](../clocked_state.py)先建立读占位和组合next，再统一闭合主副寄存器。条件put后写优先；put_exclusive用于已证明互斥的状态/深度分支，避免串联许多选择器。全部356项状态同步更新，包括CPU、目标帧和指令快照。

## 2. 每帧遍历

ENTRY检查目标网格非空有效及列A。非法内部标签返回4；不满足必要条件则本帧失败。初始化最高不同S前缀，并先进入零Pin扫描。

第一遍PREFIX只遍历全部S前缀，检查新增NPC块支撑及两个互补稳定半形。命中即调用两遍制造ROM，随后完整比较本帧目标。这样不会因为较大的前缀需要Pin，而在较小的直接起点之前陷入昂贵的Pin搜索。

零Pin遍历耗尽后，只有含C、最低C不在地面且深度小于四的目标，才重置前缀开始第二遍。每个允许S前缀P，遍历四列0～19来源槽及完整0～3顶格；同一C掩码内NPC顶盖按模3遍历，C列成员固定0，再推进C掩码及四个模20来源槽。完整顶盖仍恰有256种。坏列及物理筛选失败可[跳过整段游标](pin-cursor.md)，只跳过已有否定依据的地址。组合部件拒绝空余槽、列约束及已证的物理必要矛盾。

通过筛选时，把候选D的20份ID写入下一帧，父帧的目标和游标保持。子帧失败后回父帧的SOURCE_NEXT。子帧成功后返回真实原生结果；父帧原生Pin并逐格比较P。失配跳过同一C掩码的其余NPC顶盖；相同才虚拟追加不超过五份NPC层，并完整比较父目标。

源地址耗尽后换下一个S前缀；第二遍前缀耗尽后才宣告本帧失败。根帧失败才发布2。没有搜索预算或超时转不可制作的路径。

## 3. 为什么一份子配方就足够

一个固定D无论有多少制造历史，成功后原生结果都相同。父帧只检查Pin(D)及S追加，它们不依赖历史。因此子帧找到第一份制造证书即可返回；父Pin失配时无需继续寻找D的其他制造历史，直接换下一个结构候选，保持完备。

搜索中可以保存、查询和复制原生图形信号。它们只作为证书数据，尚未发布实体制造指令。六个物品槽的真实消费约束仍由recipe_step检查。

## 4. 保存参数后重放

每次成功叶端记录leaf_depth。向根返回时，各层成功的S前缀及Pin来源游标不再改变。因此根成功时，0～leaf_depth帧就是一条完整成功路径。

控制器将活动深度改为leaf_depth，清空六槽、ack、PC和遍次位，再执行同一份叶端ROM。此时才允许指令快照的valid为真。叶端完成并与该帧完整目标相同后，逐层减深度；每层执行11行Pin/S尾程序，继续消费槽0，逐格比较该层目标。到根时还直接比较原目标原生信号，完全相同才发布1。

这避免保存数百份包，也不会把搜索中失败的分支输出给实体工厂。整个发布流从空槽开始，基础料才创建物品，后续操作消费输入。请求从1开始交替，空操作和控制跳转不发包。六槽合法性及末端比较任一失配均返回4，不得转成2。

最多输出`2×475+4×11=994`份实际指令；该数包含了不会实际发包的控制行和条件空行，故是保守上界。理论627节点的存在性界不等于这份通用ROM已经生成最短配方。

## 5. 终止与覆盖

每个Pin目标保留全部C，其前态至少含有一颗低一层的强制C。每次递归最低C严格降低，故最多四条边、五帧。所有局部游标有限，失败后严格移动到下个来源或前缀，因此全搜索终止。

可靠性从真实角叶端开始归纳：父帧仅在原生Pin等于所选P、按层追加等于本帧目标时返回成功；重放又独立逐层比较。因此状态1对应从基础料开始的合法制造流。

完备性由标准化历史`A→S→(Pin→S)^k`归纳。k=0时第一遍涵盖全部起点及S前缀。k>0时第二遍包含末S的P；[二十槽唯一覆盖](pin-patterns.md)和四种顶格包含其前态结构，必要筛选不排除真实来源，子目标最低C降低，归纳必可求证。父原生操作再确认该历史，故根全穷尽才不可制作。

## 6. 分支互斥

Phase的每个旧状态只发布下列互斥事件：

| 旧状态 | 分支 |
|---|---|
| ENTRY | 进入、列A失败、内部网格无效、根cu、根输入无效 |
| PREFIX | 零Pin叶端、Pin遍次来源、跳过前缀 |
| PREFIX_NEXT | 前缀推进、第一遍重启Pin遍次、最终耗尽 |
| SOURCE | 合格候选下降、候选不合格 |
| SOURCE_NEXT | 地址推进、全部地址耗尽 |
| LEAF / REPLAY_LEAF | 首遍回零、第二遍结束、加工错误；首遍回零不改Phase |
| LEAF_CHECK | 匹配返回、失配内部错误 |
| RETURN | 回父、根开始重放 |
| FAIL | 回父续搜、根不可制作 |
| PARENT_CHECK | Pin不匹配、Pin和尾部均匹配、尾部内部失配 |
| REPLAY_PARENT | 程序结束、加工错误 |
| 重放比较 | 回上一层、根完成、内部失配 |
| DONE | 保持 |

CPU加工错误使advance为假，不能同时触发结束事件。相同旧Phase中的布尔分支互斥，不同旧Phase也互斥。深度只有下降、搜索成功回父、失败回父、重放回父及根跳到leaf_depth五类互斥动作。因此并行别名选择不会稳定地产生冲突。

## 7. 时序及实际边界

当前蓝图34701平台，保留频道1211000～1276535。最大状态变化路径166级，完整初始路径183级；阶段684信号tick，周期2736tick，即228模拟秒，复位至少2864tick。

所有动态路径统一满足`3P > 12D+36`，按[主副锁存证明](clocked-control.md)在下一主组关写前稳定。跨帧选择、标签查询、融合洪泛、末端比较均计入D。本版没有依赖猜测的“读两次相同即完成”。

每个完整window上升后等96tick，在窗口内读一次；sample为真先收包，再处理done/status。快照与操作在同一阶段2更新；完成比较至少在下一周期发生，故末包不会被done提前丢弃。启动不完整阶段3忽略。其余导入、模式、独占频道前提沿用时序合同。

每帧最多1296个S前缀，每前缀的原始来源地址上界为`20^4×4^4=40960000`，另有最多四层子搜索。这个穷尽界远超实用等待，不能用“有限”和“帧数少”代替游戏内性能验收。接下来仍须减少来源地址、消除无效循环及缩短冻结状态下的制造周期。

验证：两个Python文件ty诊断为0；生产编译通过DAG、端口、别名及实际建筑占地静态检查。没有游戏导入或运行验证。
