# Mari 的 TMAM：接线、Python 模型与覆盖性

已从 Mari 原包重建主控的六候选组合逻辑，并写入 [Python 模型](../mari/README.md)。51 路下发频道均找到对应接收接口；四份特殊角模板表也已核对一致，并给出其 41 种列模式的理论分类。

**尚不能确认这台机器覆盖全部可制作的四象限五层图形，也没有证实它存在漏解反例。** 当前缺口在六候选拆解的全图完备性、实体制造路径，以及自动控制的时序。接线可解析、虚拟比较相等和实体成品正确是三件不同的事。

## 1. 对象与版本

本机原件为 `shapez2_tmam/data/group_files/Mari的TMAM.zip`，大小 1,533,080 字节，SHA-256 为 `573cfd23dcd0149fd77279ce86287f19c04e1c3485d87b1a9b27ee4aaeeb89cd`。

包内是五份独立 `.spz2bp`，没有完整 `.spz2` 存档。用户报告已经在游戏内复刻；本记录检查的是下载原包，不能直接证明复刻存档的摆放、开关和跨蓝图物流连接相同。

| 蓝图 | 顶层 Entries | 建筑条目 |
|---|---:|---:|
| TMAM CMAM Factory | 619 | 140,095 |
| TMAM CMAM Trains | 1,192 | 4,896 |
| TMAM Hybrid Layer Makers | 420 | 58,076 |
| TMAM Hybrid Trains | 520 | 3,000 |
| TMAM Brain Exo | 90 | 168,718 |

封装为 `SHAPEZ2-4`，内部 `V` 和 `BinaryVersion` 为 1137。封装中的 4 不是象限数；四象限五层范围来自图形配置和实际电路。游戏规则对照本机 `1.2.0-rc3`；`Game.Content.Features.dll` 的 SHA-256 为 `c93f84ebe219d974b4aa778a73311c5d776ff6d5f90e48337671e0ee480bca07`，`resources.assets` 为 `4a2b93cd7d359162cb06df9e64025eb139eefa91fdbfc9b5191a3073b7840bd8`。未完整核查蓝图历史版本的全部迁移差异。

以下 Pn 是对应蓝图 `BP.Entries` 的零起始索引，后面的 `(X,Y,L)` 是建筑岛内坐标。不同蓝图的 Pn 不能混用。

## 2. 已恢复的接线

主控端口定义来自游戏资源，连接规则对照 `BuildingBlueprint`、`BuildingIODataFactory`、`SignalNetworkSystem`、`PortSystem`：平台坐标乘 20 后加建筑坐标；建筑 R 已是全局朝向；镜像先翻转 Y 和端口方向，不改变端口索引；跨线桥两对端口分别连通。

主控有四处短距接收器存在多个候选，位于 P2、P12。依据游戏的远端优先和竞争消解规则，这两个平台均为：

- `(11,3,0)` 接 `(7,3,0)`。
- `(9,2,0)` 接 `(4,2,0)`。

固定目标、候选编号和面板选项后，成功比较器的依赖闭包无环，没有未解析的短距接收器。加入指令和中间观察端后，正式 Python 方程包含 28,097 个节点、30,703 个输出槽。五个主控外部无配对接收器不在该核心闭包中，不能仅凭它们认定主控断线。

CMAM Factory 另有十二处信号短距竞争：P386/P387 的 y=9/10/11，以及 P389/P390 的 y=8/9/10，L 均为 0。x=-17 的接收器取 x=-12 的发送器；x=-13 被阻塞。这些接线已静态核对，尚不等于实体加工完成核查。

还已读出五份蓝图所用的全部 88 类建筑端口定义。实体带短距口和平台自带输入输出另有配对边界，不沿用主控信号短距口的四项修正。

## 3. 原包面板与成功含义

Brain P79 主面板的原始配置如下：

| 开关 | 坐标 | 原包配置 |
|---|---|---|
| TEST SHAPE INPUT | `(22,16,0)` | 开启 |
| ROS Channel | `(29,-8,0)` | 关闭 |
| Shape Board Channel | `(29,-7,0)` | 关闭 |
| Auto Tester | `(29,-6,0)` | 关闭 |
| Pin For Gap Replacement | `(29,-5,0)` | 关闭 |
| Claw Flood Color Saving | `(29,-9,0)` | 开启 |
| Update Factory | `(29,2,0)` | 关闭 |

固定目标常量位于 P79 `(20,15,0)`：

```text
crcr----:RgRgRgRg:cbcb----:cwcw----:cccccccc
```

P79 `(8,2,0)` 比较的是 P60 处理后目标与 P80 虚拟重建结果，状态广播频道为 `CcCcCcCc`。它不读取实体产物。

实体回传独立使用 `RrRrRrRr`：Hybrid Layer Makers P366 `(14,11,0)` 读取传送带，`(14,15,0)` 发射；Brain P79 `(9,-3,0)` 接收，`(12,-2,2)` 比较，再接 `(12,-1,2)` 显示器。因此主控绿灯不等于实体产线已经交付。

P60 的补针预处理含反馈环。原包补针开关为 0 时，控制门静态化简为原目标直通；开启后的反馈行为没有纳入当前 Python 组合边界。

## 4. 六种候选与指令

候选母线由 P59 `(9,5,0)`、`(14,4,0)` 驱动。自动控制的编号选择连成 `-1 → 1 → 2 → 3 → 4 → 5 → 6 → -1`；手选优先，其次取成功记录中的最小编号，否则取当前自动编号。

| 候选 | 已定位的差别 |
|---|---|
| 1～4 | P2/P12/P28/P42 支撑过滤分别使用 `{1,3}`、`{2,3}`、`{2,4}`、`{1,4}` 等条件组合；不是同一结果简单旋转 |
| 5 | 启用特殊掩码；P53 以最高可交换层作为阈值下限；P70 两个 `I != 5` 条件关闭 |
| 6 | P53 阈值下限取 5；固定其余输入时，组合结果与编号 -1 相同，但自动控制中的作用不同 |

群文件《TMAM逻辑（草稿）》描述四次尝试，不能直接替代原机六候选规则。Python 保留实际门连接，不按草稿猜测缺失分支。

51 路下发地址均已对应：

| 主控 | 频道类别 | 接收端 |
|---|---|---|
| Brain P25 | `Cr------` 角前缀，11 个命令 | Factory P478 |
| Brain P39 | `Cg------` 角前缀，11 个命令 | Factory P477 |
| Brain P57 | `Cb------` 角前缀，11 个命令 | Factory P480 |
| Brain P76 | `Cc------` 角前缀，11 个命令 | Factory P481 |
| Brain P86 | `CwCbCu--`、`CwCcCu--`、`CwCmCu--`、`CwCyCu--`、`CwCwCu--` | Hybrid 五组，各 7 个接收器 |
| Brain P86 | `CwCgCu--`、`CwCrCu--` | Factory P616 |

默认工厂地址为 `------Cr`。地址拼接中的形状只作信号编码，不是被加工的目标。

全部 51 路最终门受 Update Factory 控制。假值指令被编码为 Conflict；工厂接收保持电路收到 Null 时可保留旧指令，收到 Conflict 时清空。因此关闭更新既不等于停机，也不保证工厂持有当前目标的指令。Python 为返回“开启更新时将发送的指令”，固定此开关为 1。

## 5. 已落实的理论结果

[角模板分析](mari-corners.md)给出一项额外的列内必要条件：同列两颗晶体之间若有间隙，至少要有两个普通块，且下方晶体紧邻的上一格非空。证明沿晶体的制造历史追踪，不排除含顶针的循环支撑。

结合 Q、J 和顶针直接支撑条件，五层以内含晶体悬空间隙的列模式分成 13＋16＋12＝41 种。P18、P35、P49、P68 特殊表的键逐项覆盖这 41 种模式，三组输出常量也完全一致。这证明该表没有遗漏上述列模式；还没有证明归一化、控制数据和实体加工对每个模式都正确。

[最终拼合代码](../mari/assembly.py)明确表达了 P80 的两次角配对、半形交换、可选顶针和五级 Hybrid 堆叠。图形物理逐条保留游戏的关键顺序：

- 切割按原融合关系碎晶，再分组下落。
- 堆叠上料统一提高六层，不预删晶体。
- 顶针先删除原第五层，再上移和补底针，按原融合关系顶破。
- 一次下落不合并新接触的组；截高后不再次下落。
- 交换先分别切割结算，再拼合，不对拼合结果再结算重力。

晶体 `DestroyOnFallDown=true`、`AllowChangingColor=false` 已从本机资源核对。信号分析器、拆层器的输出不能视作实体制造步骤。

## 6. 尚未完成的全覆盖证明

设 R 是从约定基础输入经合法实体加工得到的集合，F₁…F₆ 是固定选项后的六候选重建函数。全覆盖至少需要：

```text
对每个 T ∈ R，存在 i ∈ {1,…,6}，使 Fᵢ(T) = T。
```

目前没有完成这个全称命题。既有 [K 支撑闭包、堆叠约化和单列理论](README.md)不能直接填补缺口：完整两列半形 H 和有顶破时的完整逆向仍未解决；更不能把 264 个独立单列误当作所有半形的列投影。

此外还需证明两个连接关系：

1. 主控接受的四角和 Hybrid 指令，能由实体设备与约定原料制造出来。列车蓝图使用沙盒种子，含多层晶体材料；其存在不等于从基础输入开始的完整制造证书。
2. 实际自动控制会等待正确候选、保存正确编号并使产线完成目标切换。游戏 `SimulationCluster` 按连接优先级安排更新，`SignalBuffer` 使用自适应延迟；主控依赖最长链的 538 条边不能解释成 538 tick。

实体输出末端的静态追踪目前到达 P366 的平台输入边界。五份独立蓝图的跨平台运输和复刻存档的实际连接还没有完整核对。

## 7. 检查方式与使用边界

本次使用蓝图静态解码、资源端口读取、源码重读、图结构分析和 Python LSP。没有运行目标求解、图形枚举、功能测试、游戏或浏览器。样例库、表格和群文件中的成功记录不作为全覆盖证据。

要构成确定的漏解反例，需要同时给出目标的合法制造路径，并证明六个原机候选均不能重建它。仅发现某个辅助表无匹配、某个候选失败，或者某个稳定形状不在分类中，都不够。
