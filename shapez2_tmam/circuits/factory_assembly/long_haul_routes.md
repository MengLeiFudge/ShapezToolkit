## 接轨与装载

按各站 `rails.arrival.outside_tile` 接入站轨，按 `rails.departure.outside_tile` 接回外轨。`tile` 是实体页签内已经放置的直轨，`rotation` 是该直轨的原生朝向。基础料各路从 `Y=-19` 接北侧外轨，结晶从 `Y=8` 接南侧外轨。路线表给出两端接点和停靠顺序，外侧干轨按场地连接。

四路基础料车都按原 12 节装载表编组，以 `q2、q3、q1、q0` 排列。每角三节自底到顶分别装 `C/R/S`、`W/空/空`、`r/g/b`。结晶车一节，自底到顶装 `r/g/b`。同一个车厢层的四个装卸口都对应同一货种。`stops[].unloads` 列出实用卸货位、接收平台及西口的建筑坐标 `[X, Y, 层]`。[工道页签与装载接口](stage_pages.md)

## 录入实测量

将 [卸货 CSV](long-haul-unloads.csv) 另存为实测记录。每行由工段地址、站点类别、车厢、层和卸货行唯一定位。记录实际送进该行缓冲的货量 `measured_amount` 和对应的平均到货间隔 `measured_interval_seconds`。空白表示尚无实测数据，零表示该行实际没有收到货。表中 `min_amount_per_visit` 按规划间隔计算，单位为件或升。60 秒示例中的满带 C 行至少要收 120 片，制针红行至少要收 2400 升。

实际间隔与规划不同时，用实测货量除以实测间隔，核对是否达到该行的 `required_per_second`。货层还须覆盖该路线各停靠点的合计，缓冲按最长断货间隔检查。第四路的红层每趟需求最高，实机按该层和各站第 28 行分别记有效卸量。一满带仍以实测到货量和成品出带共同判定。

```bash
python -m shapez2_tmam.circuits.factory_assembly.long_haul_routes --output-dir long-haul --base-routes 4 --headway 60 --belt-rate 2
```

输入不同车队数量或规划间隔时，可重导对应站点表和空白录入表。
