# 145 道悬空配方的六槽工道页签

两张可导入的实体页签覆盖地址 `110–127`。这是覆盖该订单全部九种实际工序的最短连续区间。两张页签共接四个 12 节基础料混合车站和一个单节结晶混合车站，按冻结配方布点。[页签接口和 145 道布点表](stage-pages.json)

| 页签 | 地址 | 3×3 平台 | 供料站 |
| --- | --- | ---: | --- |
| [工道 110–118](stage-page-110-118.spz2bp) | 110–118 | 145 | 110 结晶，115、116、118 基础料 |
| [工道 119–127](stage-page-119-127.spz2bp) | 119–127 | 108 | 120 基础料 |
| [共用控制](stage-page-controls.spz2bp) | 全线 | 8 | 双回读接管、长度放行、停料和成品过滤信号 |

## 扩建和接页

```bash
python -m shapez2_tmam.circuits.factory_assembly.stage_pages --output-dir stage-pages
python -m shapez2_tmam.circuits.factory_assembly.stage_pages --window 0 145 --page-size 9 --output-dir stage-pages-full
```

省略 `--window` 时只重导两张代表页签。完整导出仍按页分文件。`--window START STOP` 使用左闭右开地址，可单独重导或补建某页。安装全线时，共用控制页签只放一次。代表页签作为全线的中段，所需活槽由前段送入。单独验收这些工段时，需按配方回放准备其入口活槽。

每页第一道的六槽取料台是定位基准，对应 `pages[].place_at`，全线工段 `i` 的原点为 `(18i, 0, 0)`。页内已接好本页最后一段至下一页前的六条桥。两张代表页签的页间发送台在 `(2139, 0, 0)`，下一页接收台在 `(2142, 0, 0)`。两台按建筑层 `0` 的 `−12、−9、8、11、28、31` 行对齐，东西口间隔五格。扩建时按不同绝对地址重导页签，保留各地址的译码和存储频道。末段 `144` 东侧在 `(2598, 0, 0)` 接六槽合流和成品过滤，成品由第 `31` 行输出。

工道保留通用加工台。按这份配方剪裁站点时，全线需要 49 个基础料站和 6 个结晶站，其余 90 道只保留加工及槽带。与每个地址都给两种站的布点相比，少 96 个基础料站和 139 个结晶站。换任意配方时，提交前按 JSON 的每地址 `allowed_opcodes` 检查。需要在任意地址执行基础料或结晶指令时，对相应页使用 `--universal`，两种供料站会同时保留。现成 94 道直接落角样件换入时，地址 66 须补结晶站，72、74、78、80 须补基础料站。145 道是本样件的容量需求，通用整厂还须按求解器实际发送上界确定容量。

## 送料与单带检查

单料火车先卸入配料站，按接口 `load` 装到混合车。同一层四路同货。基础料车按 `q2、q3、q1、q0` 排列，每角三节的装载依次为 `C/R/S`、`W/空/空`、`r/g/b`，自底到顶。结晶车一节装 `r/g/b`。每张已导出页的 `rails` 给出进出轨和外接岛格，`supply.unload_rows` 给出全程 214 个实际用料的地址、车厢、建筑层与卸货行。轨道和缓冲按实际到站情况接入。

代表段每件需要 16 片 C 和 80 升红染料。地址 110 的红结晶从单节车第 1 节底层第 28 行领 20 升。地址 115、116、118 分别从 12 节混合车的第 12 节底层第 28 行各领 20 升制针红。整线每件需 C/R/S/W 分别 177/6/6/1 片，红/绿/蓝分别 440/20/10 升。满带 `B=2` 件/秒时，第 1、4 节基础料车底层的 C 各需持续分发 94 片/秒。每行用实测有效卸量除以到站间隔核对，最久的无到货间隔内仍需足够缓冲。

未升级时成品满带为 120 件/分钟。首个堆叠在地址 2，代表段有 117、119、121 三处堆叠。通用工段各用一台堆叠机，按 2.5 秒加工等待的上界每台至多 24 件/分钟，送料等待还会降低持续速度。两个输入与末端合流在一带目标下各需承担 120 件/分钟。一满带需要补足并联加工能力，并实测落料、进机、合流和卸货供给。[通用产能核算](README.md#一满带核算)

## 动态主控和换单

| 时点 | 信号和条件 |
| --- | --- |
| 置 `RUN=1` 前 | 发布目标 `1600000`、长度 `1640043=145`、实际回放结果 `1640044`、成功位 `1640045=1`。结果须等于本次目标，指令地址 `0–144` 都已有硬件且所需站点齐全。保持这些信号至订单排空。 |
| 逐笔装方 | 随公开地址 `1640000` 发布候选地址 `1680007` 和 `opcode/a/b/destination/base/color` 六字段 `1680001–1680006`。未用字段发空，真实槽 0 和地址 0 发整数 `0`。按上游稳定上界配置提交桥，保存当前六字段至本笔双回读确认，再响应新地址。 |
| 放行领料 | 最后一笔完成双回读 `2→3→1`，工道发布 `1640057=1` 后，才把 `ENABLE_FEED=1640059` 置 `1`。控制页签使用 `RUN=1640030` 和 `CLEAN_CONFIRMED=1640060` 装方。 |
| 换单 | 先停料，维持旧配方处理在途品，末端切到废料口。检查页间六槽带、双输入加工机和成品带，清掉残留及单边料。实物清空后将三个开关置 `0`，使总线相位 `1640001=3` 连续至少 128 信号 tick，再用新装方信息启动。 |

动态提交桥沿用现有发布协议。桥在六字段稳定后同时发布 `1640002–1640007`，读回吻合后才给 `1640046` 地址标签。工道用 `1640011` 请求和 `1640013` 确认本笔。装方与到货均需满足，成品才会通过末端过滤。换短单时，连续清空也覆盖后段未重写的地址，使其回到六槽直通。页间几何、卸货层行、双回读与复位接线已离线核对。实体锁存、残量清空、到货和持续出带留待实机验收。[动态提交桥与换单细节](README.md#动态提交桥)
