# 六槽实体装配

`layout.assemble(count, packet_tag=...)` 生成原生岛蓝图和可序列化的站场接口表。每个地址对应一个工段，通用工段带六槽直通带、两个操作数入口、加工回带、四角基础料和独立结晶供料。`recipe.replay(target, packets)` 用同一组六字段回放物品，保留两个操作数的顺序、目的槽和被舍弃的半形。回放结束时，唯一活槽须等于目标形状。

## 外置主控生产线

在仓库根目录按所需工段数导出。每个工段包含六槽加工、基础料与结晶收料，配方由外置主控发送。

```bash
python -m shapez2_tmam.circuits.factory_assembly.production --stages 2 --output six-slot-production.spz2bp
```

导入 `.spz2bp` 后，按同名 JSON 的 `interfaces.recipe` 接主控与换单开关，按 `interfaces.stations` 和 `interfaces.load` 接供料，按 `interfaces.output` 接成品带。`--stages` 须在 1 至 971 之间，并覆盖主控会发送的最长配方。Python 可调用 `production.build(count)` 取得同一份原生蓝图文本和接口表。

通用含晶线可选用双回读接管和单平台结晶收料。[动态含晶工道重导、接线与用量](mixed_sample.md)。

通用工段可用 `--compact-base` 将卸货并入四角选料台。[基础料合板、车头位置与共用供货下界](base_feed.md)。

四色长单的混编车分层装载、到站频率和整片直达样件见[40／41 道四色长单供货](long_order_supply.md)。

### 纯堆叠三册

```bash
python -m shapez2_tmam.circuits.factory_assembly.production --direct-stack --output 纯堆叠/实体/direct-stack-production.spz2bp
python -m shapez2_tmam.circuits.factory_assembly.books proportioning --direct-stack --output-dir 纯堆叠/配料
python -m shapez2_tmam.circuits.factory_assembly.books trains --direct-stack --output-dir 纯堆叠/通用火车
```

使用通过纯堆叠判定且回放吻合的目标。地址 0、1、3、5、7 各接一处四角混装站，可领取任意基础单层。地址 2、4、6、8 各有六台并联堆叠机，槽 0 和槽 1 分别在底层和上一层分流，每台接收一对操作数，统一回带写回槽 0。配方长度为 1、3、5、7 或 9，后续已清空的工段通过六槽直通带。

按实体册 `interfaces.stations` 中的 `base_head` 接朝北的混合列车。沿用 12 节车厢、28 项角位货种对应的车厢编号和层位。基础备料内部的顶针支路由混合车供应红染料，整线省去独立结晶站。配料册提供七种基础料的换装站和混编车库，通用火车册提供图形与流体单料模板。成品由最后一台平台的东口输出一条带。一满带的供货余量按实际目标和到货量核算。

使用下文 `--direct-stack` 的动态提交桥和装方信息板。工道沿用六字段总线、整单放行和 128 tick 清空流程。同名 JSON 额外列出各工段 `opcode` 及合法的 `supported_lengths`。Python 可调用 `production.build_direct_stack()` 取得蓝图文本和接口表。

### 动态纯堆叠接管样件

```bash
python -m shapez2_tmam.circuits.factory_assembly.direct_sample --output direct-dynamic-handoff.spz2bp
```

样件将发布册的六个纯堆叠电路、动态提交桥和九段实体接管工道合装为一份蓝图。同名 JSON 的 `circuits` 和 `submit_bridge` 列出信号频道，`interfaces` 列出操作开关、配料接点和成品带口。纯堆叠的颜色字段始终发空信号，槽 0 以整数 `0` 传输。

换单先停料并排空旧单。工道进入复位后即可送入新目标 `1600000`，将写入相位 `3` 的 128 tick 连续清空等待与新目标计算并行。按 `timing` 保持目标至稳定，在扫描开关为 `0` 时完成扫描复位，再置 `1` 启动扫描并等待采样和装方信息收敛。扫描开关用 `circuits.direct-stack-scan.inputs.run`。清空等待完成、装方信息收敛且回放吻合后，打开工道 `RUN` 和 `CLEAN_CONFIRMED`。等 `loaded=1` 再开料。

离线回放按板内组合信号同刻传播、跨板无线延迟 12 信号 tick 建模。两层与五层订单分别确认 3、9 笔，覆盖地址 0、末地址、双回读和换单清除。五层从启动装方到 `loaded=1` 为 22,104 信号 tick。实体锁存和供货速率仍需实机验收。

## 无尾针双半形拼装

`half_assembly.join_corner_half_instructions` 接左角（主列 q0、助手 q3）与右角（主列 q1、助手 q2）的活槽。`join_built_halves_instructions` 接两个朝 q0/q1 的标准半形，`alternate=True` 按另一切向恢复原方向。缺席的一侧传 `None`。可指定 `destination`，该槽须为空或是本次消费的操作数槽。省略时优先写回左角或前半形槽，只有右角或后半形时写回其所在槽。

`append_five_instructions` 按从低到高的原层顺序接收至多五份基础单层，跳过 `None`。`has_lower=True` 时把尾料逐份取入空的 `upper_slot`，堆叠后写回 `lower_slot`。无下料时第一份直接领入 `lower_slot`。三段指令按实际调用顺序拼接，`recipe.replay` 核对唯一成品，再沿用现有地址和六字段提交。未用字段发空信号，实际槽 0 发整数。

制作第二个半形的第二角时，可把第一个半形和同半形的第一角保存在槽 5 和槽 4。主形占槽 0，近锚占槽 1。先用 `corner_release.pin_corner_handoff_instructions(0, 1, counterclockwise=direction, reserved_slots=(4, 5))` 在槽 2、3 搭远柱，交接后只剩主形和两个保留槽。此时在槽 1～3 备制补形，完成后调用 `pin_corner_top_break_instructions`。两段须传同一个 `counterclockwise`。主形备制可用四槽，备近锚和补形时各可用三槽。交接阶段占满六槽，补形备制若用满三个工作槽也达到六槽。保留两个槽时，补形须在交接后领取。

| 接合工序 | 最多工段 |
|---|---:|
| 两角合半，每个半形 | 5 |
| 两个半形拼合并恢复切向 | 3 |
| 有下料时追加五份无晶体单层 | 10 |
| 无下料时纯堆叠五份单层 | 9 |

四角已就绪时，合半、拼合和尾料共至多 23 段。单次顶破的支撑交接为 17 或 18 段，补形就绪后的顶破为 2 或 4 段。若四角都需顶破，四段释放加接合工序共至多 `4×22+23=111` 段。完整指令长度还须计入各角主形、近锚和补形的实际备制，以及释放后的补层、末切和定向。

## 两步配方提交样件

```bash
python -m shapez2_tmam.circuits.factory_assembly.sender_sample --output two-step-sender.spz2bp
```

蓝图包含两段工道和固定发送器。第一笔把基础料 `Cu------` 放入槽 2，第二笔从槽 2 取料结晶并写入槽 0，目标为 `Cucrcrcr`。目标和已回放的结果同时发布。每笔的槽号、基础图形和颜色随六字段一起提交。未用的操作数、图形与颜色发空信号，第二笔的目的槽发整数 `0`。

候选计算使用同名 JSON 中的 `sample.private.fields`。发送器先比对候选地址和预期的六字段，再发布 `commit_address`。两个发布板接收同一个提交地址，在它与当前工段地址相等时一起打开。发送器读回公开的六字段，全部匹配后才回送 `packet_tag`。

向 `sample.start` 指定的频道发布整数 `0` 并停料，持续观察 `phase=3` 至少 128 信号 tick。样件每隔 12 tick 取一次清空相位，12 个样本通过才在 `sample.reset_ready` 指定的频道发布整数 `1`。两个条件满足后，向启动频道发布整数 `1` 并保持。样件发布 `RUN` 和 `CLEAN_CONFIRMED`，供料开关仍由操作方控制。待 `loaded=1` 后开料，换单先按下文排空再重新清空。

## 动态提交桥

```bash
python -m shapez2_tmam.circuits.factory_assembly.submit_bridge --settling-report fields.json --output submit-bridge.spz2bp
```

将提交桥与外置主控工道合装，保留接口表的 `reserved_internal_channels` 范围。编译器的六个输出接 `1680001–1680006`，本组使用的工段地址接 `1680007`。桥从工道读取当前地址、长度和复位信号，是公开六字段及 `packet_tag` 的唯一发送器。目标、配方长度、实际回放结果和操作开关由主控发布。按本次配方留空未使用字段，整数槽号 `0` 保持原值。

单块计算板用编译报告的 `settling.hold_signal_ticks`。多块板串接时，用 `--hold-signal-ticks` 传最长路径上各板等待时间的合计。当前纯堆叠编译的四个整数值并行需要 1,344 tick，基础图形要先取深度再取层，合计 1,664 tick。

接验收册的纯堆叠电路时，用 `--direct-stack` 随桥导出候选地址板。装方信息板发布 `accepted=1` 后，候选地址板转发有效的工道地址到 `1680007`，桥照常等待并核对字段。纯堆叠不使用结晶颜色，`1680006` 留空。

```bash
python -m shapez2_tmam.circuits.factory_assembly.submit_bridge --direct-stack --hold-signal-ticks 1664 --output direct-submit-bridge.spz2bp
```

主控在发出候选地址后，保持计算所用的目标、长度及其他输入，并保持当前候选直到工道确认。桥比较每个私有字段与 12 tick 之前的值，为每个地址累计等待时间。等待向上取整为完整无线跳数。比较采用固定无线相位，前提是编译板在整组输入保持时按报告收敛，或外置来源按同样的固定相位提交。候选地址不符、字段变化或工道复位会清空相应等待记录。复位仍须执行下文连续 128 tick 的清空流程。

等待器每 12 tick 读取上一轮的地址和计数。首次看到有效地址时把计数置零，此后只有地址连续相同才递增。各位读取同一轮旧值，低位全部为 `7` 才进位。等待 `N` 个无线跳时，确认板读到 `N−2` 即提交，首轮初始化和末轮确认各占一跳。提交后只要同一地址持续具备资格，提交地址便保持有效。任意一次读到空资格或新地址都会重计。单跳等待直接转发资格。此递推使用同一套板内无环、跨板无线 12 tick 的时序条件。[原生时序证明](../../docs/proofs/08-circuits.md#s08-05-h1)

纯堆叠按 1,664 tick 配置，实际等待 1,668 tick。加 `--delay-chain` 可导出原来的无线延迟链，供离线逐拍对照。下表统计带 `--direct-stack` 的整座提交桥，建筑数包含导线。

| 等待方式 | 等待平台 | 提交桥总平台 | 提交桥建筑 |
|---|---:|---:|---:|
| 八进制计数器 | 4 | 15 | 13,344 |
| 无线延迟链 | 139 | 150 | 36,008 |

等待到期后，两块板一起发布暂存的六字段。提交地址到公开数据为 12 tick，公开数据到回读标签为 24 tick。两组回读确认属于当前地址且六字段吻合，工道才收到标签。桥原样转发图形与颜色信号。

## 写入与换单

`assemble` 的接口表包含 `recipe`，验收与实体册 JSON 在 `interfaces.recipe` 导出同一张接线表。每项信号的值是原生频道编号，`length` 给出这张蓝图的可装配长度。精简工道还需按 `stations` 核对每个地址的基础料和结晶停靠点。

| 字段 | 信号方向与用法 |
|---|---|
| `controller_outputs.target`、`replay_result`、`accepted`、`length` | 主控发布目标形状、回放得到的形状、成功整数 `1` 和指令总数。回放结果必须等于目标。长度须在 `length.min..length.max` 内 |
| `controller_outputs.payload`、`packet_tag` | 主控按地址发 `opcode/a/b/destination/base/color` 六字段。工序和在用槽号用整数，`base` 和 `color` 分别用原生图形和颜色信号。动态主控将未使用的字段留空。读回总线并确认六字段与当前地址匹配后，才回送该地址为 `packet_tag` |
| `factory_outputs.address`、`ready`、`request`、`ack` | 工道发布从 0 起的地址。`ready=1` 且标签匹配后，工道置 `request=1` 并开始写入。发送器保持地址对应的六字段和标签，直到 `ack=1`，再随工道地址更新。只响应 `0` 到 `length-1` 的整数地址。整数 `0`（包括首地址的标签）与空信号含义不同 |
| `factory_outputs.loaded` | 最后一笔确认且整单回放、长度和放行条件仍满足时，工道发布 `loaded=1`。此时可打开领料，实体交货以东侧成品带实际经过的图形和数量为准 |
| `factory_outputs.reset`、`phase`、`readback` | 工道输出复位、写入相位和两个存储组的回读。一次写入需两个回读都依次通过 `2 → 3 → 1`，工道才发出 `ack=1`。待机和复位都会使两组回读为空，复位完成按下方的保持时间判断 |
| `operator_outputs` | 换单外控提供下表三个开关。排空时保持旧目标、回放结果、成功位和长度，让旧配方继续处理在途品 |

固定发送器在导出前已由 Python 回放，所以把预验证的目标作为 `replay_result` 回送。动态主控须发布本次配方的实际回放结果。接入动态主控前，移除固定发送器的岛，确保这组频道只由一个发送器发布。

`stream_controller` 选择旧状态或后继、复位值或下一状态时，正反支路各经过一级门。两支读到同一份控制信号时同时切换。板内同拍和无线 12 tick 的推导适用于批量导入或完整重载后的固定接线、独占频道及 Hybrid 或 AlwaysHighUPS 常速更新。[原生时序证明](../../docs/proofs/08-circuits.md#s08-05-h1)

写入相位 `1 → 2 → 0` 依次覆盖写入、写入与保持重叠、只保持。发送器保持当前地址的六字段，直到该笔 `ack=1`。三阶段保持要求反馈缓冲先全部取得同一值。现有回读在匹配当拍即可发出，离线核对只确认相位门控和字段比较，写入器与存储板的本地反馈仍需实机确认。[三阶段寄存器证明](../../docs/proofs/08-circuits.md#s08-29)

两组回读 `3` 由写入使能和当前字段相等产生，保持路可能还未接管。两组回读 `1` 核对当时的储值。可沿用六字段及现有回读频道给写入器增加等待。收到两组 `2` 后，写入阶段须留足同值覆盖反馈的时间。进入重叠阶段后，保持当前地址和六字段，直到保持路稳定接管。撤去写入后，再等写入驱动完全关断并看到两组 `1`，才确认该地址。换到下一笔前等待 `ready=1` 和双回读清空。实机观察每个阶段的持续时间、储值和地址推进。

### 双回读接管样件

```bash
python -m shapez2_tmam.circuits.factory_assembly.writer_handoff --output writer-handoff.spz2bp
```

样件带两笔固定发送器和两地址存储板。第一笔领 `Cu------` 入槽 `0`，第二笔从槽 `0` 结晶，目标为 `Cucrcrcr`。在 `sender.select.channel` 发布整数 `1`，保持 `RUN=0` 并按下方流程复位，再置 `RUN=1`。同名 JSON 的 `stored` 列出每个地址的六个储值频道。可在 `loaded=1` 后读取，确认槽 `0` 的整数和未用字段的空值各自保留。

控制器按当前相位分别等两组 `2`、`3`、`1`。每次双组匹配后，须再经 11 轮无线反馈计数才推进，在 12 tick 固定无线模型中为至少 132 tick。重叠阶段保持写入直到反馈接管。撤去写入后，两组 `1` 仍须通过同样的等待才发 ACK。地址推进的条件、旧值和后继使用同拍采样，避免提交条件仍有效时读到下一地址的后继。

按本地每门一拍、导线同拍运行离线模型时，原写入器可出现相位冲突，地址推进也可提前换到后继。样件在无线 1 拍和 12 拍两种模型中都按 `0 → -1 → 1 → -2 → 2` 推进，每笔回读 `2 → 3 → 1`。在 12 拍模型中，三个写入相位分别维持 278、271、333 拍。从 `RUN=1` 到 `loaded=1` 为 1909 拍，覆盖两次装方以及重叠中途复位后重跑。游戏内锁存和持续出货仍由 #72 验收。

集成时在 `changeover.controls` 接入 `writer_handoff.stream_advance` 和 `writer_handoff.writer_modules`，对应原推进板和写入板。保留两组存储板和六字段频道。新控制板需独占 `1683000–1683004`，并为四块写入控制板重新排位。整线仍按下方步骤清空，样件的 `stored` 频道只用于观察。

### 复位等待

初始化和换单时，将下表三个开关保持为 0，并在写入总线上观察 `phase=3` 连续至少 128 个游戏信号 tick，再开始装方。空回读只表示当前没有写入回报，待机时存储板仍可保留旧配方。

在上述常速更新条件下，`phase=3` 同时关闭写入路和保持路。无线传播用 12 tick。两条关断路径最多经过四个控制门、一个写入或保持门，再到存储导线和反馈输入。最长路径按 12 条本地缓冲边、每边预留 8 tick 计算，总计最多 108 tick，128 tick 留出余量。该等待只针对配方电路，实物按下表排空。[本地缓冲与无线传播依据](../../docs/proofs/08-circuits.md#s08-34)

实机先用两段工道，在停料时核对地址 0、1 各自的两组回读 `2 → 3 → 1` 以及随后的 `ack=1`。最后一笔确认后应看到 `loaded=1`，打开领料后才应看到目标成品。复位后换一份比旧配方短的订单，核对未重写的工段保持直通。

| 阶段 | `RUN` | `CLEAN_CONFIRMED` | `ENABLE_FEED` | 操作 |
|---|---:|---:|---:|---|
| 初始化或复位 | 0 | 0 | 0 | 停料并复位工段。等写入总线进入 `phase=3`，按复位等待保持 128 个信号 tick |
| 装方 | 1 | 1 | 0 | 在空线发布稳定的新目标、回放和配方。等待 `LOADED=1` |
| 生产 | 1 | 1 | 1 | 保持目标和配方。基础料开始进线，匹配目标的实物进入成品带 |
| 排空 | 1 | 1 | 0 | 保持旧目标和配方。停止领料，末端切入废料口，让在途品按旧路径排出 |
| 清空确认后复位 | 0 | 0 | 0 | 从入口选择器下游到成品口检查槽带、支路、缓存和机内。清除仍卡在双输入机器中的单边物料，再允许复位并换目标 |

`CLEAN_CONFIRMED` 由操作方在检查后提供。停料后先排空在途物品。双输入机仍有残料时，选中对应建筑并清空选区内容。游戏的建筑清空操作会调用 `StackerSimulation.ClearContent`，清掉两侧输入、加工位和输出位。使用整岛清空前先隔离需保留的原料与固定色管线。若仍有残料且无法清理，在断开进料后重建该段。收货方也须排空成品过滤器之后的出货带。

纯堆叠地址 2、4、6、8 各有六条并联支路。停料后保留旧配方，让可配对的物料走完。检查堆叠平台底层 A 和上一层 B 的两个分流组，再逐台检查第 `-15、-9、-3、18、24、30` 行的两侧输入、加工位和输出位。清理剩下的单边物料时，一并清空两层分料带及分流器，恢复分流初始顺序。确认东侧合流干线、跨台带和成品口也已清空，再确认 `CLEAN_CONFIRMED`。

## 供货接口

工段 `i` 的装配原点为 `(18i, 0, 0)`，列车车头方向朝北。`assemble` 返回每段车头位置和末端出带坐标。`layout.cargo_ports()` 为配料和制作提供同一份货种、车厢、层和接收行表，车厢从车头后第 1 节起算，层从 0 起算。

| 车种 | 装载 | 配料端接口 |
|---|---|---|
| 单料车 | 所有货厢及占用层保持同一种整片或原色 | 使用 `factory_book` 的同类型车库、装货站和卸货站 |
| 基础料混合车 | 从车头起按 `q2、q3、q1、q0` 重复三节一组。三节分别装 `C/R/S`、`W/空/空`、`r/g/b` | 用 `freight_loader.loading(cargo)` 装指定货，并以 `freight_stage.depot()` 生成编组 |
| 结晶混合车 | 一节流体车，从底层起装 `r/g/b` | 用 `layout.crystal_loading(cargo)` 将指定原色的底层四路装进混合车对应层。各换装板接连贯通的单向铁路线 |

每个图形货层目前在对应角料台使用一条带。每个原色货层有四路独立管，供直通及不同混色支路。不同管路的剩余运力须按实际接管位置分配。车站和装卸方向应核对至每一个使用的端口。

## 一满带核算

先将通过的 `Production` 交给 `capacity.demands`，取得每个加工路径和每节车每层每行的单位成品需求。`check_capacity` 用成品带速乘需求量得到每秒所需件数或升数。输入每种机器、物品带路径和染料管路径的持续实测速率。各路径使用同一个速率参数时，取该类路径的实测下限。将每条站场缓冲每趟实际收到的货量填入 `TrainDelivery`，除以平均到站间隔得到该路供货率。供给量按实际卸货计，库存只用于缓冲。

每台机器和每条进料路径的供给率均须满足每秒需求。对已有供给记录，`parallel_lines` 取各需求除以单线供给率并向上取整的最大值，得到所需的独立生产线数量估算。计算依赖每条线具有独立供料和处理能力，合流后的出带也须达到目标带速。缺测的速率或零供给会使并联数量无法确认。多线的频道与站场分配、实机供料、换单和持续一满带一起验收。

### 九工段纯堆叠的供货上界

设成品满带为 `B` 件/秒。五层目标在地址 0、1、3、5、7 各领一层。四格的形状与颜色完全一致时，`q0` 领一片整片后直通。四格同形但颜色有差异时，四条角料线各领一片。混合角料中的空角和顶针都领一片无色圆。每片染色耗 10 升，每片制针在六次顶针之间结晶一次，耗红色 20 升。[供料选路](../layer_supply.py) · [四角拼装](../quarter_join.py) · [用量与混色配比](../../synthesis/production_bill.py)

| 货种 | 单角货层最高 | 单个供料站最高 | 五站合计最高 |
|---|---:|---:|---:|
| `C`、`R`、`S`、`W` 各自 | `B` 件/秒 | `4B` 件/秒 | `20B` 件/秒 |
| 红色，仅染色 | `10B` 升/秒 | `40B` 升/秒 | `200B` 升/秒 |
| 红色，含制针 | `20B` 升/秒 | `70B` 升/秒 | `350B` 升/秒 |
| 绿色、蓝色各自 | `10B` 升/秒 | `40B` 升/秒 | `200B` 升/秒 |

各货种的上界按目标分别取。将 `CrCgCbCw` 重复五层会到达圆片上界，其他形状可套同一颜色组合。`CrRrSrWr` 重复五层会到达纯染色的红色上界，改为全绿或全蓝可分别到达这两色的上界。`P-P-P-Cr` 重复五层需 20 片圆和 350 升红色。第四格也是顶针时，该层改走整片直通，每件只需一片圆和 20 升红色。[已回放配方的需求计算](capacity.py)

| 单角加工 | 流体车层内的有效卸货行与流量（升/秒） | 混色或加工段最低供给（升/秒） |
|---|---|---|
| 红、绿、蓝直染 | `r:28`、`g:31` 或 `b:31` 各 `10B` | 一条直染管 `10B` |
| 青 | `g:28` 与 `b:29` 各 `5B` | 一台混色机输出 `10B` |
| 品红 | `r:29` 与 `b:28` 各 `5B` | 一台混色机输出 `10B` |
| 黄 | `r:30` 与 `g:29` 各 `5B` | 一台混色机输出 `10B` |
| 白 | `r:31` 需 `5B`，`g:30`、`b:30` 各 `2.5B` | 中间青色 `5B`，白色输出 `10B` |
| 顶针 | `r:28` 需 `20B` | 一条制针红管 `20B` |

图形车每角的 `C/R/S` 在首节的底、中、顶层用第 `-12` 行，`W` 在第二节底层用第 `8` 行。每个货层到角料台只接一条带，选择台在东口第 `9` 行合为一条。每条启用的角料带、拼装回工段的单带和堆叠的两条输入及单条输出均需 `B` 件/秒。每台启用的图形加工机也需处理 `B` 件/秒。末端单带为平台 `(150,0,0)` 的东侧底层第 `31` 行。[实体装卸表](../../blueprints/验收/实体/纯堆叠/direct-stack-production.json) · [领料带](../stock_selector.py)

流体第三节每层接四个卸货行。红色底层第 `28` 行通往直染和制针两个支路，同一固定角料只启用其中一路。制针时，红料经过同一条入口管和制针红管，图纸上流量要求最高。若该路只能持续送 `P` 升/秒，涉及顶针的订单最多出 `P/20` 件/秒。以地址 0 的 `q2` 为例，流体车在 `(-12,-14,0)`，卸到 `(-9,-15,0)` 平台西口的 `(-18,28,0)`。该平台把制针红色从东口 `(37,31,1)` 送出，角料加工台从 `(-18,11,1)` 接入。两级白色混合的每一级也只有一条出口管。[混色和制针分流](../wagon_intake.py) · [角料加工入口](../angle_prep.py)

固定循环下，用有效卸货行的平均每趟缓冲入货量 `Q`、平均到货间隔 `T` 和该行的需求 `D` 核算 `Q/T ≥ D`，缓冲还需覆盖最长的无供货间隔。同一混编车服务多站时，每个车厢层须覆盖沿途各站的有效卸货量之和。`1.2.0-rc3` 的 `TrainCargoUnloaderSimulation` 每层把四个出口接到同一货包容器，`TrainCargoToBeltFillingContainer.Update` 按出口顺序向能接收的带交货，按每条实际使用的带或管记录 `Q`。染色及结晶还受机器输入、输出带的运行时间约束，见 `PainterSimulation.DeltaTicksBetweenPaints` 和 `CrystalGeneratorSimulation.DeltaTicksBetweenCrystallization`。带、管、混色机、加工机和列车任一路的持续供给低于表中需求，都会限制该订单的出带。

纯堆叠的首个堆叠工段在地址 2。`1.2.0-rc3` 的普通直带速度为 1 格/秒，`LaneConstants.ItemSpacing` 为半格，未升级时一带为 120 件/分钟。`StackerStraightInternalVariant` 的加工等待为 2.5 秒。`StackerSimulation` 在加工位有料时锁住两侧输入，清空加工位后才允许下一对物料继续走约半格。持续有料且出口无阻塞时，按约 3 秒一对估算，单台约 20 件/分钟，六台约 120 件/分钟。实测还要计入调度、进出机和到货造成的空档。[堆叠平台](layout.py)

串接的五级二分流在六路都能接收时，按 `1/2、1/4、1/8、1/16、1/32、1/32` 分配。当前两层各用一次二分流，再让每组经一个三分流供三台，六路均能接收时各得 `1/6`。原生轮转分流会跳过堵住的出口。每台满带工况需 A、B 各 20 件/分钟。六个出口依次合到同一条底层干线，原生合流器轮换已排队的输入。最下游合流口、平台东口及下游单带各承担 120 件/分钟。两路进料的干线也各需 120 件/分钟，其中一路断供会使另一侧在机内积料。记录稳定段的双层入口、六台产量和东口产量，即可区分缺料、机内等待和合流回堵。

## 接入 Solver4 的成功配方

在仓库根目录生成指令 JSON，再用同一个验收入口编译实体工道和固定发送器。

```bash
python -m shapez2_tmam.synthesis --complete --instructions 'CucrCuCu' > solver4-order.json
python -m shapez2_tmam.circuits.factory_assembly.acceptance --recipe solver4-order.json --compact --output solver4-acceptance.spz2bp
```

`--recipe` 读取带 `status: solved` 的四象限五层指令 JSON。导出先按六槽消费语义回放，再按指令数生成实体工段。每条指令的六个字段原样进入发送器。邻接 JSON 中的 `stage_capacity` 给出容量，`interfaces.stations` 给出停靠点，`interfaces.load` 给出车厢层位，`orders.solver4.paths` 给出每件所需的供料路径。`--compact` 仅安装该订单用到的供料站。

也可把同一份 JSON 分别交给三个分册命令。实体册使用精简站场，并保留单带运力表。

```bash
python -m shapez2_tmam.circuits.factory_assembly.books physical --recipe solver4-order.json --output-dir 验收-订单/实体
python -m shapez2_tmam.circuits.factory_assembly.books proportioning --recipe solver4-order.json --output-dir 验收-订单/配料
python -m shapez2_tmam.circuits.factory_assembly.books trains --recipe solver4-order.json --output-dir 验收-订单/通用火车
```

实体册的 `interfaces.load` 与配料册的 `load` 使用同一张装载表，车厢和层位保持原有编号。配料册为实际用到的货种生成对应换装站，区分四角备料和工道结晶。通用火车册按需生成图形或流体车站，`cargo` 将各货种映射到 `shape` 或 `fluid` 的车库、装货站及卸货站模板。在单料环线上为每种货各用一套模板。省略 `--recipe` 时，三个命令生成前一节的双订单验收分册。

实机按下节先清空工道，在 `sender.select.channel` 发布整数 `1` 选择这份配方。地址回读、写入应答、装方结束和领料放行沿用同一组信号。

## 实机接入与验收

1. 导入验收工道。按 `interfaces.stations` 对接基础料车和结晶车。单料车先卸入配料端，再按 `interfaces.load` 装混合车。逐个核对使用的车厢、层位和行的货种、流向与制作端接收到的实物。
2. 保持 `RUN`、`CLEAN_CONFIRMED` 和 `ENABLE_FEED` 为 0，确认工段已复位。在 `sender.select.channel`（默认 `1640047`）发布整数 `1` 选择 `stack`。订单发送器会设置目标、配方长度和回放成功信号。
3. 按[写入与换单](#写入与换单)放行装方，等待 `LOADED=1` 再启用领料。从 `interfaces.output` 指定的东侧带口验收，记录收到的目标图形、稳定出货时刻和成品数。
4. 停料并保持旧订单，观察废料口并检查全线在途品。清除双输入机两边的残留，排空槽带、加工支路和成品过滤器之后的出货带。复位并确认写入状态清空，再在 `sender.select.channel` 发布整数 `2` 选择 `pin-crystal`。按同一出货口记录新成品，确认换单后出货带只出现新目标。
5. 记录游戏版本、带速档位、每种加工机和管带的持续速率、每个有效卸货行的实际到货量和到站间隔。各订单从启动缓冲稳定后开始连续观察，覆盖各有效停靠点的多个到站周期。用成品数除以游戏内观察时间计算出货率，并检查供料库存是否持续下降。

设目标带速为 `B` 件/秒。两份订单的每个在用工序及单带路径都须保持 `B` 件/秒的成品当量。顶针结晶订单的两处工道结晶机与各个在用制针结晶机分别需要 `20B` 升红染料/秒。该订单全线合计需要 `77B` 件 C 整片/秒与 `160B` 升红染料/秒。默认 `--belt-rate` 为 1，便于按比例换算。示例命令里的 3 仅用于演示完整带速的填法，验收按实际档位填写。堆叠机的持续速率取决于游戏的加工延时和带速配置，还受上下料和输出阻塞影响。

给实体册传入 `--measurements` 可填写持续加工率、实测卸货量和到货间隔。记录格式如下。`base` 是基础料混合车，`crystal` 是结晶混合车。速率和货量支持整数、小数或分数字符串。各订单只检查实际使用的工段与端口。

```json
{
  "rates": {"belt": "3", "pipe": "100", "StackerStraight": "2"},
  "deliveries": [{
    "stage": 0, "station": "base", "interval_seconds": "10",
    "payload": [{"wagon": 10, "layer": 0, "row": -12, "amount": "20"}]
  }]
}
```

`capacity.<订单>.loads` 按车厢和层汇合需求。`paths` 仍逐条带或管列出需求。若某路每秒需求为 `R`，实测每趟收到 `Q`，到站间隔 `T` 秒，则每趟至少需 `R×T`，最大到站间隔为 `Q/R`，每分钟至少到站 `60×R/Q` 次。同站各路取最严格的到站要求。`lowest_measured_capacity` 给出已记录的最低供给／需求比。`unknown_capacity_checks` 为 0 时才能据此判定最慢工段。持续一满带以实机验收第 5 步的记录为准。

## 无尾针的双半形拼装

[`half_assembly.py`](half_assembly.py) 的三个入口返回按发包顺序排列的六字段指令。按顺序连到前面的备料指令即可。缺失的角、半形和尾料用 `None` 表示。槽 `0` 是有效地址。配方发令前用 `recipe.replay` 核对整单成品和末槽。

| 入口 | 输入槽和结果槽 | 最多工段 |
|---|---|---:|
| `join_corner_half_instructions` | 左角主列和助手在 `q0/q3`，右角在 `q1/q2`。消费存在的角，结果默认进第一个存在的输入槽 | 5 |
| `join_built_halves_instructions` | 两个半形均以 `q0/q1` 为正面。先转第二半形再拼合，按 `alternate` 恢复切向。可指定 `destination=0` | 3 |
| `append_five_instructions` | 按原层号从低到高领无晶基础单层。指定 `lower_slot` 和空闲的 `upper_slot`。`has_lower=False` 时第一份尾料直接进入下料槽，之后复用上料槽 | 10 |

合角和拼半形的目标槽可用输入槽或空槽。先保留前半形，再保留后一半的第一角。最后一角若需顶破，先备好主形和近锚，再用 `pin_corner_handoff_instructions` 搭远柱并转交支撑。此时两个保留槽、主形、近锚和搭远柱的两个槽恰占六槽。备近锚时只需两槽造柱，另保留主形和两个外部产物，峰值五槽。转交后远柱、近锚和临时槽均已释放，可在三个空槽内备补形，再用 `pin_corner_top_break_instructions` 消费补形并写回主槽。两段使用同一个 `counterclockwise` 值。

两次合角、一次拼半形和最多五层追加合计至多 23 工段。加上四个角的顶破释放，每角至多 22 工段，合计至多 111 工段。预算整单时还要计入主形、近锚和补形等备料，以及角本身可能需要的后续拼接和恢复朝向。

## 紧柱与触顶补形备料

[`dense_column.py`](dense_column.py) 的两个入口都返回六字段指令。`dense_column_instructions` 接收从底到顶的单格短代码，每层原料放在 `q0`，空信号只用于补齐末尾层。调用时给出两个空槽 `destination` 和 `scratch_slot`。普通格保留原形状和颜色。有色晶体先领 `P-CuCuCu`，旧颜色在下一种晶色到来或完工时一次结晶。纯普通格与顶针的柱也可以直接备制。含晶柱的真实针尾通过 `append_five_instructions` 追加。最后两次半切移除 `q1/q2/q3` 的临时料，将紧柱存入 `destination`，上料槽释放。单根五层紧柱最多 18 工段。

`pin_complement_instructions` 接收 `pin_corner_trigger` 给出的单格层序，三个空槽分别作结果、触顶柱和临时上料。先造五层红晶脊，再造触顶柱，按 `counterclockwise` 转向并交换。调用时可同时保留前半形、第一角和已转交支撑的主形，备制峰值为六槽。补形存入 `destination` 后，另外两个槽可复用。当前构造用三至四层触顶柱，最多 25 工段。入口允许五层，最多 27 工段。补形做完即可接 `pin_corner_top_break_instructions`。

## 工段容量与共用供料

当前装配让每个配方地址占一个工段。两份订单中较长的一份有 48 条指令，因此固定双订单示例需要 48 段。两份订单的地址 `0、1、5、7` 都领取基础单层，地址 `2、6、8` 都走堆叠。这七段可随换单重用同一路径，基础料选择器按当前订单领货。

```bash
python -m shapez2_tmam.circuits.factory_assembly.acceptance --compact --output six-slot-compact.spz2bp
```

精简蓝图安装两份订单地址并集所需的 21 个基础料停靠点与 2 个结晶停靠点。地址 3 随订单在接收基础单层与结晶之间切换，因此保留两个停靠点。两处结晶地址为 3 和 32。实际站位以 JSON 的 `interfaces.stations` 为准。只接表中给出的 `base_head` 和 `crystal_head`。示例仍按每个地址保留加工工段和槽带，内置发送器供这两份固定订单使用。

| 动态工段预算 | 依据 | 通用布置的岛项目数估算 |
|---|---|---:|
| 616 | [理论制造树上界](../../docs/proofs/02-four-quadrants.md#s02-06-h7)。要用这个容量，输出器须保证每次都选到不超过 616 条的制造流 | 48,666 |
| 971 | [既有四帧程序的保守发包上界](../../docs/proofs/08-circuits.md#s08-09)。也对应当前工段地址及写入门控上限 | 76,711 |

估算按通用布局每段含 75 个岛项目、相邻段间 4 个六槽桥、全线共 6 个出口及控制项目计算。动态整厂的实际工段容量取编译后发送器可能发出的最大物理指令数，统计基础料与加工指令，扣去控制行及不发指令的分支。发送器上界确认后，再用 `layout.assemble` 的通用配置生成并核对该规模的蓝图。

合并同货供给时，先列出同一订单下同时取料的所有支路。目标带速为 `B` 件/秒时，支路每件成品需求乘 `B` 后在同一分流干线上求和。换单后两份订单互斥，共用干线按两份订单中的最大合计需求定容。每条带或管用持续实测速率，列车还要满足每一层每一行的实际卸货量除以到站间隔。缓冲要能支撑两个到站批次之间的领料。相同货种可在上游共用装载站或车队，下游须有足够的并行带路及分流。

例如，顶针结晶订单两处工道结晶合计需要 `40B` 升红染料/秒，四角备料中的制针另用 `120B` 升/秒。若结晶与制针支路共用上游红染料干线，持续供货需达到 `160B` 升/秒，并分别送达每个活跃卸货行。若把 77 路 C 整片需求上收至同一个上游干线，持续供给需 `77B` 件/秒。同档带的单路持续速率等于 `B` 时，至少占用 77 路带。若每个同货车厢层的四路都能并行有效卸货，还至少需要 20 个这样的满载层位等效供给。工道精简示例继续使用各地址的车站、固定车厢位置和独立缓冲。实机验收按各路到货数据确定合并能力。
