# 40／41 道四色长单的车队和供料

使用已发布的两份指令回放物料请求，再按车辆、货层、地址和卸料行分别累计。基础料停靠地址为 `0、1、7、8、17、18、24、25、36、38`。结晶停靠地址为 `3、10、20、27`。两单切换后共用这些地址，`36、38` 的四角换向会改变实际使用的货层。工道容量和槽位沿用已发布样件。[四色配方与逐行需求](../../blueprints/验收/实体/四色含晶/four-color.json)

```bash
python -m shapez2_tmam.circuits.factory_assembly.long_order_supply --belt-rate 2 --fleet-interval 60 --output long-order-supply.spz2bp
```

默认导出三段可导入样件。同名 JSON 的 `long_orders` 用 40／41 道真实配方列出每层循环总量、每行持续用量和按指定到站间隔所需的最低缓冲。默认示例按未升级的一带 `B = 2` 件/秒和每 60 秒来一班车计算。

## 沿线同一班车的货层需求

| 线路 | 车厢／层 | 货种 | 40 道每件 | 41 道每件 | 共线 60 秒最大需求 |
|---|---|---|---:|---:|---:|
| 基础料 | 1／0 | C | 7 | 7 | 840 件 |
| 基础料 | 4／0 | C | 7 | 9 | 1,080 件 |
| 基础料 | 7／0 | C | 7 | 7 | 840 件 |
| 基础料 | 10／0 | C | 7 | 5 | 840 件 |
| 基础料 | 7／1、10／1 | R | 2、1 | 0、3 | 240、360 件 |
| 基础料 | 1／2、7／2、10／2 | S | 2、0、1 | 0、2、1 | 240、240、120 件 |
| 基础料 | 2／0、5／0、11／0 | W | 0、2、1 | 2、0、1 | 240、240、120 件 |
| 基础料 | 12／0 | 红 | 80 | 80 | 9,600 升 |
| 结晶 | 1／0、1／1、1／2 | 红、绿、蓝 | 30、30、20 | 30、30、20 | 3,600、3,600、2,400 升 |

主单占用混编车 11 个货层，换向单占用 10 个。保留两单的装载时，基础料车需要上表 13 个有需求的层位，结晶车需要 3 个。两单每件合计同为 C 28 件、R/S/W 各 3 件、红 110 升、绿 30 升、蓝 20 升。表中共线列按每层取两单的最大值，车队可按当前订单使用 JSON 中对应的实际用量。沿用配料的四路同料约定。

对货层 `l`，设沿途所有站合计每出一件成品消耗 `d_l`，每趟有效补入量为 `Q_l`。车队频率至少为 `f = max_l(B × d_l / Q_l)` 班/秒。单个卸货行也要分别检查 `f ≥ B × d_row / Q_row`，以免车厢总货量达标而某站分不到料。完整周转耗时 `T_loop` 时，车数至少为 `ceil(f × T_loop)`。每行的有效缓冲须覆盖最长无货间隔 `G`，下界为 `B × d_row × G`。60 秒示例下，一条满载整片行需 120 件缓冲，四个制针地址的红色底层第 28 行各需 2,400 升。结晶地址 27 的红、绿两行各需 1,200 升。最小实班频和车数取决于实测有效卸量、周转和最长间隔。

## 共用车队与接轨

同一队 12 节混编车可按表服务十个基础料地址。另一队单节流体车可依序服务四个结晶地址。长单稳态下这些地址同时领料，沿途各站分货量需要同时成立。起线时若前站接料缓冲仍空，先验证后站达到了启动库存再放开生产。两类车可以共用外侧干轨，再各自进入匹配车长和车厢次序的支线。合计班次要在最窄共享岔口留出两类车各自的占用及清空时间。当前原生样件保留各站接轨口，实际共线频率和道岔调度由到站记录确认。

两单的地址 0 都只领 `CuCuCuCu`。地址 1 同时已经从第 10 节底层领 C。若把两站并到地址 1 的选料后单带，那条带要送 `2B`，超过一条满带。每层四路同料仍可支持将来另取一条独立卸货行。共用一个当前的卸货行会遇到上述单带上限。四个结晶地址保留独立工作管口，单节车依次送达各站。红、绿各 `30B` 升/秒和蓝 `20B` 升/秒都由各自货层承担。

## 41 段整线与两路车队

```bash
python -m shapez2_tmam.circuits.factory_assembly.long_order_supply --mode four-color --output four-color-banked.spz2bp
python -m shapez2_tmam.circuits.factory_assembly.long_order_supply --mode four-color-direct --output four-color-direct.spz2bp
```

两条命令从同一份 40／41 道发布配方生成整线和固定发送器。`four-color` 的基础料站都用四角合板，`four-color-direct` 把地址 0 换为整片直供。两版都附西、东两条基础料路线的原生接点和各车层需求。

| 41 段验收线，含发送器 | 3×3 平台 | 岛项目 | 建筑 |
|---|---:|---:|---:|
| 基础料与结晶均合板 | 683 | 1,154 | 745,633 |
| 地址 0 采用整片直供 | 671 | 1,142 | 733,156 |

按地址 `0、1、7、8、17` 与 `18、24、25、36、38` 分车，41 道订单第 4 节车底层的 C 从 `9B` 件/秒分为两路的 `4B` 和 `5B`，基础料制针红由 `80B` 分为两路各 `40B`。满带每秒 2 件、每 60 秒一趟时，C 层每路分别需卸入 480 和 600 件，制针红层分别需 4,800 升。整片直供保留地址 0 的第 10 节车底层、第 −12 行，每秒需 `B` 片 C。两版都按同一装载表和 46 个有效卸货行核对 41 道订单。

同名 JSON 的 `fleets` 列各路线 `stops` 及逐订单用量。每站的 `arrival.rail` 和 `departure.rail` 是蓝图自带的进、出两根接轨，`next_tile` 给接在外侧的相邻岛格。以地址 `i` 计，基础料进、出轨分别为 `(18i−10,−18,0)` 和 `(18i−9,−18,0)`，向北接外轨。结晶进、出轨分别为 `(18i−6,7,0)` 和 `(18i−7,7,0)`，向南接外轨。`long_orders` 的每个有效卸货行还列出卸货站、接收平台及建筑层坐标。装车和干线由实际铁路停靠计划接入。实际到货、运行频率和持续满带继续按 #72 验收。

## 整片直达样件

三段样件依次在地址 0 领无色整圆、地址 1 领 `P-CuCuCu`，再叠入槽 0。地址 0 只开 `q0` 的第 10／11 节卸货，其他车位保留原车种对应的占位站。原选料过滤器根据工道领料信号开带，整片依次跨台进入收料台原北口。第二个站仍是完整四角备料。两站继续接收同一种 12 节混编车，槽位和成品口由接线表给出。操作发布器、清空和放行沿用六槽写入流程。

该约束在真实两单只命中地址 0。将 41 段压缩实体线的基础料、结晶与双回读配置保持一致，启用整片直达后从 1,070 降到 1,058 个岛项目，建筑从 603,239 降到 590,762。小样件自身为 134 个岛项目、62,835 个建筑，含三步发送板。出货目标还受加工速度约束。两单均在地址 `2、9、19、26、37、39` 堆叠，现有通用工道各选一台堆叠机。按 1.2.0-rc3 未升级的 2.5 秒加工等待计算，即使忽略送料，每台也至多 24 件/分钟，低于 120 件/分钟的成品带。列车侧达到表中的数值后，仍需核对加工与实机满带。[既有工段速率核算](README.md#一满带核算)
