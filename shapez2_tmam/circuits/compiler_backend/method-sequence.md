# 方法串行启动与阶段确认

```bash
python -m shapez2_tmam.circuits.compiler_backend.method_sequence \
  --pair-job-dir path/to/pair-job-boards \
  --output method-sequence.spz2bp
```

将 `pair-job`、`pair-job-inputs`、`pair-job-cursor` 的原生蓝图和同名 JSON 放到 `--pair-job-dir` 指定的目录。导出时核对合装件的原生发射频道和主控板稳定时间。同名 JSON 列出频道与保持时间。省略 `--pair-job-dir` 可单独导出确认器。

样件用五组子方法端口，每组采用 256 信号 tick 的复位保持期和 160 tick 的启动后采样期。实际接入时可重复指定 `--method KIND RUN DONE RESET_TICKS SAMPLE_TICKS`，按各子方法接口表填写。`--settle-ticks` 取当前阶段的参数稳定上界，`--update-ticks` 取主控 `next` 的稳定上界。两项默认均为 1536 tick。

| 频道 | 方向 | 含义 |
| --- | --- | --- |
| `1701690` | 确认器 → 主控 | 当前 `phase`，复位初值为整数 `0` |
| `1701691` | 主控 → 确认器 | 当前 `kind`，`0` 跳过，`1`–`5` 分别调用子方法 |
| `1701692` | 主控 → 制造子方法 | `destination`，目的槽 |
| `1701693` | 主控 → 制造子方法 | `left`，左输入槽 |
| `1701694` | 主控 → 制造子方法 | `right`，右输入槽 |
| `1701695` | 批次控制 → 确认器 | `enable`，`0` 复位，`1` 运行 |
| `1701696` | 确认器 → 主控 | `settled`，阶段参数或子方法结果可供主控计算 |
| `1701697` | 确认器 → 主控 | `confirmed`，当前非空方法已确认 |
| `1701698` | 主控 → 确认器 | 由 `pair_job_next` 一类的方法计算的下一阶段 |
| `1701699` | 主控 → 确认器 | `done`，主控到达终止阶段后置 `1` |

同一阶段内保持 `kind` 和子方法参数。每次非空调用先让对应子方法的 `run` 保持 `0`，等满复位保持期并看到该方法的 `done=0`，才拉高 `run`。等满采样保持期并读到 `done=1` 后，确认器回传本次请求的整数 `phase`，等主控的 `next` 稳定后提交。未配置的非零 `kind` 等待对应确认。子方法的 `done` 须在复位完成后发整数 `0`，完成后保持整数 `1` 到下一次复位。

中断或换单时把 `enable` 保持为 `0` 至少 72 信号 tick，并保持各子方法规定的清理条件。再次启动会对首个子方法重新执行拉低、等清零和采样流程。按整件导入或完整重载、固定频道每边 12 tick 的条件使用。

合装件从 `1700766`–`1700769` 读取四列高度，从 `1700871` 读取切向，并在 `1700873` 发布列号。导入合装件时一并接入五组子方法的 `run` 和 `done`。样件的 84 个无线发射频道各有一个发射器，包含合装件内的主控板输出。

离线回放使用合装件的原生接线，模拟子方法的 `done`。在每次启动时，`kind`、列号和三项槽位与 `pair_jobs` 一致。验证覆盖 phase 0、连续两次同 kind、空工序、五种 kind、末笔和中途换单。强制保留旧 `done=1` 时，当前阶段保持且子方法未启动。放开旧 `done` 后按原顺序到达 phase 9。游戏内时序待验。
