# 顶针尾帧写入

调用前，槽 `0` 保存前态，槽 `1` 留作本次追加的临时槽。上级控制冻结同一次顶针的结果与目标，按原层位从底到顶各送五行。空行发空信号。尾帧先发 opcode `6`，然后逐层计算差量。非空差量先用 `14` 装入槽 `1`，再用 `7` 叠回槽 `0`，空差量直接越过。每次调用最多发 11 笔。

| 频道 | 用途 |
| --- | --- |
| `1703900` | 启动，`1` 运行，`0` 复位 |
| `1703901` | 本帧完成，保持到启动拉低 |
| `1703902`–`1703906` | 目标五行，由底至顶 |
| `1703907`–`1703911` | 冻结的顶针结果五行，由底至顶 |
| `1701761` | 合装版的主方法运行口，尾帧运行时保持 `0` |
| `1701762`–`1701764` | 共用桥的请求地址、当前地址、同址 ACK |

五行在本次启动前给定并保持到完成。共用桥保留 `164` 段工道协议及 `1680001`–`1680007` 候选总线，实际地址由工道推进。确认时钟每步等输入稳定，非空指令等待本笔同址 ACK。连续调用先将启动拉低至少 72 信号 tick，确认 `1703901=0` 后再启动下一帧。工道地址在同一订单内连续递增。整单换单沿用工道的清空与复位协议。

## 重导

输入目录含 `tail-frame-level`、`tail-frame-row` 和 `tail-frame-packet` 的原生蓝图与同名 JSON。指定 `--writer` 时，输出含原有 writer、尾帧和一份共用写入桥，可替换原 writer。写入桥选择尾帧或主方法，尾帧门控要求主方法运行口为 `0`。

```bash
frames=.codex/tail-frame.ndNtkc
python -m shapez2_tmam.circuits.compiler_backend.tail_frame_writer \
  --frames "$frames" --output tail-frame-writer.spz2bp

python -m shapez2_tmam.circuits.compiler_backend.tail_frame_writer \
  --frames "$frames" \
  --writer .codex/corner-automatic.5RdBEi/dual/pair-writer.spz2bp \
  --output pair-writer-with-tail.spz2bp
```

## 回放结果

独立版 24 板、21,236 个建筑。用 86 板 writer 合装为 104 板、119,772 个建筑，原生频道解码确认六字段和候选地址各有一个发射器。

离线按 12 信号 tick 无线模型接工道提交桥和双回读存储。从一次尾针必需案例的前态生成 `P---P---:Cu------:crCu--Cu`。连续三次调用的工序为 `6 / 6,14,7 / 6`，地址 `0–4`。每笔公开六字段与两组存储回读逐项一致，经原生虚拟单步回放后，槽 `0` 是对应目标，其他槽为空。换成旋转目标后首笔从地址 `0` 重新写入，原订单尾部各地址保持空。游戏内时序待实机验收。
