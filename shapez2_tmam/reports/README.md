# 元件与时序报告

当前研究按“理论约化 → Python流程 → 元件数量与时序 → 游戏走线”推进。先比较分支、制造步骤、状态与组合通路；只有方案值得落实时才重新布局。

```bash
python -m shapez2_tmam.full_solver_circuit --report-only --output shapez2_tmam/reports/full-tail-4q5l.json
python -m shapez2_tmam.full_solver_circuit --report-only --pack --output shapez2_tmam/reports/full-tail-packed-4q5l.json
```

这两个命令只编译生产网表，不运行目标或模拟，不生成蓝图。`--pack`在报告模式只确定私有局部门配对及其时序权重。报告记录逻辑门分类、状态、固定配对数、DAG深度、周期和复位界。

| 方案 | 逻辑门 | 状态 / 慢状态 | 固定局部门对 | 快 / 慢 / 初始深度 | 周期tick |
|---|---:|---:|---:|---|---:|
| [全无线](full-tail-4q5l.json) | 25006 | 145 / 124 | 0 | 47 / 132 / 148 | 960 |
| [固定局部模板](full-tail-packed-4q5l.json) | 25000 | 145 / 124 | 5491 | 39 / 114 / 128 | 816 |

逻辑门包括常量、状态和控制门。它们不等于游戏建筑总数：无线收发器、复用常量和局部组件会改变建筑数量；平台装箱又影响占地。当前没有新的平台数或走线长度。固定模板的时序以最终布局保持所登记配对为前提。

直接有效行后继减少制造期间的空推进周期，整数PC删除八项状态；它也增加了组合门。因此不能只根据门数或单周期长短宣称所有输入更快。Pin搜索的最坏分支数仍是主要瓶颈。
